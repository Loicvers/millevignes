# Consignes pour Claude (dépôt millevignes)

Économiser les tokens : ne lire que ce dont la tâche a besoin.

- **Ne jamais lire `data/base.json`** : il est dérivé (`node tools/migrate-fiches.mjs`), volumineux et non versionné (`.gitignore`). Les tests tournent aussi sur GitHub à chaque push.
- Textes intégraux des sources (livre de Lepeltier, Oxford Companion, Wine Grapes, Peynaud, Dion…) : dépôt **privé** `Loicvers/millevignes-sources` (à cloner dans `../millevignes-sources`, puis `/add-dir`). Chercher avec `./cherche.sh "motif" [dossier]` (donne fichier, page et ligne) ; ne jamais ouvrir un fichier entier. **Ne jamais copier ce contenu dans ce dépôt** (droits). Une page marquée `[OCR]` : vérifier un chiffre sur l'original avant de le citer.
- Registre des sources (où est chaque document, niveau, fiabilité, usage ; WSET = niveau 2a, banques de questions = modèles d'exercices seulement) : `registre/sources-wset.md` dans le dépôt privé `millevignes-sources`. À tenir à jour à chaque ajout ou retrait de source ; ne pas le copier ici (il cite le Drive et les chemins du PC).
- Citations du livre : `node tools/verifier-citations.mjs` contrôle chaque « Selon le livre (p. N) » contre le texte du livre (nombres et noms propres retrouvés sur les pages N-1 à N+1) ; à relancer après un lot. Informatif : il ne tourne pas sur GitHub (dépôt privé).
- Erreurs du livre déjà relevées : `docs/erreurs-du-livre.md` (lire les pages du lot, compléter avant le push).
- Sources citées par Lepeltier, classées par section avec leur état d'accès : `docs/bibliographie-lepeltier.md` (lire la section du lot avant la recherche).
- Les fiches sont dans `fiches/<page>-<section>.js` (une section de Mille Vignes = un fichier, `FICHES.push(...)`). `fiches.js` ne contient que l'en-tête et les catalogues `SOUS` / `THEME_ORDER`.
- Pour ajouter un lot, ouvrir **seulement** le fichier de la section concernée. Section inconnue → créer `fiches/<page de début de section>-<section>.js` puis lancer `node tools/sync-site.mjs`. **Après tout changement du site** (fiches, app.js, style.css, exercices.js…) : `node tools/sync-site.mjs` (balises `<script>`, liste de `sw.js`, nom du cache = empreinte des fichiers ; un test échoue s'il est oublié).
- Dernier id utilisé, sans rien ouvrir : `grep -ho "^    id: [0-9]*" fiches/*.js | sort -t: -k2 -n | tail -1`
- Fiches déjà en place sur des pages données : `grep -n "page: 1[89]\b" fiches/*.js` puis lire seulement ces blocs.
- Format des exercices et contrôles : `docs/IMPORT_FORMAT.md`. Ne pas relire `docs/AUDIT_INITIAL.md` (historique).
- Contrôles : `node tools/migrate-fiches.mjs && node --test 2>&1 | tail -8` (n'afficher que le résumé ; détail seulement en cas d'échec).
- Chaque fiche porte ses pastilles : `status` (`verified` | `needs_review`) et `to_check` (faits ⚠️). Voir `docs/IMPORT_FORMAT.md`. Après toute modification de pastilles : `node tools/a-verifier.mjs` (régénère `docs/a-verifier.md`, ne pas l'éditer à la main).
- Après chaque lot ou modification : `node tools/a-verifier.mjs && node tools/etat.mjs` (régénèrent `docs/a-verifier.md` et `docs/etat.md`, seule source des chiffres) ; ajouter une ligne datée à `docs/journal.md`. Sources déjà lues : `docs/sources-lues.md` (à compléter).
- Fiches hors livre « La France viticole » : `source: "france"`, `chapitre` pris dans `FRANCE_SOMMAIRE` (`fiches.js`), pas de `page` ; un fichier par région, `fiches/fr-<région>.js`.
- Profils de cépages (hors livre) : `fiches/cepages.js`, `source: "france"`, chapitre « Cépages de <région> » de la partie « Les cépages » (`FRANCE_SOMMAIRE`), rangés par région française d’élection ; jamais sur une page du livre.
- Pastilles : seuls les faits clés restent dans `to_check` ; un détail secondaire appuyé par le seul livre va dans `selon_livre` (hors dette). Régions françaises : catalogue `REGIONS_FR` de `fiches.js`.
- Lot d'une section : suivre le skill `lot-mille-vignes` (sous-agents par chapitre, modèle selon l'étape : haiku pour l'extraction, sonnet pour la recherche et la rédaction, opus pour l'arbitrage et la relecture indépendante ; ids, écriture du fichier, contrôles et push restent à la session principale). Petite tâche (une fiche, un exercice) : sans sous-agent.
- Cartes de sous-régions (schémas des fiches France) : `tools/cartes/carte.mjs <config>.json > carte.svg` (zones = union de communes IGN, une config JSON par carte dans `tools/cartes/`), puis `node tools/cartes/poser.mjs <fichier> <id> carte.svg "<légende>" "<crédit>"`. Données à télécharger dans `/tmp/geo` (voir l’en-tête du script). Contrôle visuel en PNG avant de poser.
- Points partenaires sur toutes les cartes : `node tools/cartes/partenaires.mjs <liste privée>.json > mes-partenaires.json` (liste hors dépôt : nom, commune, dep, communeGeo, region, appellations). À relancer après chaque nouvelle carte.
- Récits de chapitre : `data/recits.js`. Chapitres hors livre (France, cépages, monde) : titre de `FRANCE_SOMMAIRE`, pas de `pages`, un `src` ; écrits uniquement à partir des fiches vérifiées du chapitre (un récit par chapitre, à chaque lot).
